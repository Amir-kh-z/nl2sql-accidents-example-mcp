# לבנות שרת MCP לתוסף התאונות שלכם — מדריך בנייה

[English](BUILD_YOUR_OWN_MCP.md) · **עברית**

> התוסף שלכם נולד מערכת הפתיחה (`nl2sql_accidents_starter`), ולכן הוא חולק עם התוסף הזה את אותו חוזה בדיוק:
> `Action` עם `run(ctx, ...)`, `Result` אחד לכל פעולה, המעטפה (מכנה, הסתייגויות, קרדיט) ב-`envelope.py`,
> הסטודיו והפנקס. כל מה שבנינו כאן תחת `nl2sql_roadsafety/mcp/` עובר אליכם אחד-לאחד. המדריך הזה הוא
> המסלול: מה להחליט, מה להעתיק, מה לכתוב, מה לבדוק — ושלושת הפרומפטים ל-Claude Code שעושים את זה איתכם.

## 1. מה תבנו

שרת MCP אחד שחושף את הפעולות של התוסף שלכם ל-Claude Code ול-Claude Desktop כקבוצה קטנה של **כלים לפי כוונה**,
עם כללי המסד כ**משאב**, נהלים כ**פרומפטים**, שורת **audit** לכל קריאה, ושער אישור לפני כל שינוי מצב. אצלנו:
30 פעולות ← 13 כלים. אצלכם: 19 פעולות הפתיחה ועוד מה שבניתם ← בערך 8 עד 10 כלים.

מה **לא** תבנו: כלי SQL חופשי. המלכודות של המסד (שתי הסדרות, המפתח המורכב, ספירות מול סיכון) חיות בתוך
הפעולות; סוכן שכותב SQL בעצמו עוקף אותן. זו החלטת עיצוב, לא מגבלה טכנית.

## 2. העיקרון — שבעה כללים

1. **הליבה בתוך התהליך.** `Context(db_path)` + `Registry(modules=[MODULE]).run(...)` — בדיוק מה שהאפליקציה עושה
   ב-`adapters.module_run`, בלי פורט 8000. "עובד גם כשהאפליקציה כבויה."
2. **כלי = כוונה, לא פעולה.** `roadsafety_sites` עוטף חמש פעולות דירוג; `roadsafety_breakdown` שלוש. ההקשר של
   המודל מחזיק 13 תיאורים במקום 30, והמודל בוחר נכון יותר. הקיבוץ הוא החלטה שלכם.
3. **המעטפה מרונדרת, לא מתורגמת.** כותרת · בסיס · מכנה · מזהה מודל · הסתייגויות · שורות (קצוב, והקיצוץ נאמר) ·
   קרדיט · תמונה. מה שהעמוד מצייר, הצ׳אט מקבל כטקסט ו-PNG.
4. **שינוי מצב עובר שער.** אימון ופריסה: טופס אישור של השרת (elicitation) כשהלקוח תומך; אחרת דגל `confirm`
   שמסרב בלעדיו ואומר מה היה קורה.
5. **audit לכל קריאה.** איזה כלי, אילו פעולות, כמה זמן, שגיאה, הערה — לעולם לא המספרים (הפנקס כבר מחזיק אותם).
6. **ידע כמשאב, נוהל כפרומפט.** הכללים הזהובים כטקסט סטטי; about/models/ledger כמשאבים חיים; "סקירת אתר",
   "המלכודת", "ממשל מודלים" כפרומפטים.
7. **stdout נקי.** על stdio כל בייט ב-stdout הוא פרוטוקול. לוגים ל-stderr; `MPLBACKEND=Agg` לפני ש-matplotlib
   נטען; ה-SDK נטען רק ב-`server.py`, לעולם לא ב-`__init__.py` של החבילה (שגיאת ייבוא של תוספת אופציונלית לא
   מפילה את הפעולות).

## 3. השרת שלנו כדוגמת ייחוס

| קובץ (`nl2sql_roadsafety/mcp/`) | תפקיד | אצלכם |
|---|---|---|
| `runner.py` | `Runner(db_path)`: Context + Registry, ברירות מחדל של הפעולות, "אין מסד" כמשפט ולא כקריסה, שורת ה-audit | **העתיקו כמו שהוא.** שנו: `from .. import MODULE` (עובד אם לחבילה שלכם יש `MODULE`), `AUDIT_REL` (`accidents_starter/mcp_audit.jsonl`), `ENV_DB`/`DEFAULT_DB` |
| `render.py` | `Result` ← בלוקים (טקסט/תמונה), טבלה קצובה ל-60 עם מקרא לעמודות העזר, שורת קרדיט | **העתיקו.** עדכנו את `COLUMN_NOTES` לעמודות שלכם |
| `tools.py` | מפת `TOOL_ACTIONS`, סגירות מוקלדות (Literal = enum, `int \| None` = אופציונלי), `face` ← `view`, הסטודיו עם `confirm` + `hard_gate` | **העיצוב שלכם.** המבנה נשאר, התוכן שלכם |

| `lookup.py` | שם ← מפתח אתר (`roadsafety_find`) | אופציונלי. שימושי אם המשתמשים שלכם מדברים בשמות |

## 4. שלב אחר שלב

### 0. תנאים מוקדמים
- התוסף שלכם מותקן בסביבת האפליקציה (`..\app\.venv\Scripts\python -m pip install -e ".[dev,ml]"`) והמבחנים ירוקים.
- הערכה הזו משובטת לידו (`..\nl2sql-accidents-example-mcp\`) — זו דוגמת הייחוס שהסוכן שלכם יקרא.
- `mcp>=2,<3` בסביבה (`install-chat.bat` של הערכה כבר התקין; אחרת `pip install "mcp>=2,<3"`).

### 1. החליטו על טבלת הכלים (על נייר, לפני קוד)
רשמו את כל הפעולות של המודול שלכם (`MODULE.actions`). קבצו לפי כוונה: התמצאות · מגמה · פירוק · אתרים · תחזית
· הסבר · סטודיו · ממצא · טריאז׳. תנו לכל קבוצה שם `<תוסף>_<כוונה>` (אצלנו `roadsafety_…`; אצלכם למשל
`starter_…` או השם שבחרתם). סמנו מי **משנה מצב** (אימון, פריסה). החליטו מי נשאר **בעמוד בלבד** (אצלנו
`map_scene` — ענן נקודות הוא לא תשובת צ׳אט). כתבו לכל כלי **משפט תיאור אחד** — זה מה שהמודל רואה. התוצר:
טבלה כמו "הקטלוג" ב-`docs/m1_design.md`.

### 2. העתיקו את השכבה הגנרית
```
nl2sql_accidents_starter\mcp\__init__.py      (ריק, עם docstring)
nl2sql_accidents_starter\mcp\runner.py        <- מ-nl2sql_roadsafety\mcp\runner.py
nl2sql_accidents_starter\mcp\render.py        <- render.py
nl2sql_accidents_starter\mcp\register.py      <- register.py
nl2sql_accidents_starter\mcp\knowledge\rules.md
```
בשלושת הקבצים: החליפו `roadsafety`/`accidents` בשם שלכם במחרוזות (`AUDIT_REL`, `ENV_DB`, `DEFAULT_NAME`), ושום
דבר אחר. הם לא תלויים בתוסף הספציפי.

### 3. כתבו את `tools.py`
- `TOOL_ACTIONS: dict[str, tuple[str, ...]]` — הטבלה משלב 1. `EXCLUDED_ACTIONS` למה שנשאר בעמוד. **המבחן
  הראשון שלכם:** `mapped ∪ excluded == {a.name for a in MODULE.actions}` — כל פעולה או מאחורי כלי או מודרת
  בכוונה. המבחן הזה הוא מה שמונע מכלי להישכח כשמוסיפים פעולה.
- כל כלי = סגירה מוקלדת על `Runner`: ערכי בחירה בעברית כ-`Literal` (הם חוזה הפעולות שלכם — עוברים כמו שהם);
  `int | None` לאופציונלי (ברירת המחדל של הפעולה עצמה); `face: Face = "auto"` ← `view_for(action, face)`.
- **החתימה היא הסכמה.** ה-SDK גוזר את הטופס מ-`inspect.signature`. אף פרמטר פנימי לא נכנס לחתימה הציבורית
  (אצלנו צעדי הביקורת נוסעים ב-`ContextVar`). מכשול 2026-09-12 ב-PITFALLS.
- הסטודיו: `STATE_CHANGING_OPS = ("train", "deploy")`, פרמטר `confirm: bool = False`, ו-`ctx: Context | None = None`
  (ה-SDK מזריק אותו, ומוציא אותו מהטופס). העתיקו את `hard_gate` ואת `ConfirmSchema` כמו שהם: יש elicitation ←
  טופס; אין ← דגל; לא אושר ← `# ⛔` ושום דבר לא רץ. `CONFIRM_TEXT` שלכם אומר מה *היה* קורה.
- `catalog_text()` — המפה כטקסט, למשאב `…://catalog`.

### 4. כתבו את `server.py`
- `MCPServer(name="<שם>", title=…, instructions=INSTRUCTIONS, version=…)`. **הפסקה החשובה בכל הפרויקט היא
  `INSTRUCTIONS`:** לענות בשפת המשתמש; לעולם לא מהזיכרון כשיש כלי; מספר רק עם העמודה שלו; המכנה וההסתייגויות
  בכל תשובה; שינוי מצב ← לשאול, ואז `confirm=true`; לעולם לא אימון ← פריסה בלי אימות; טבלת מילים נרדפות
  בעברית ← כלים. העתיקו את שלנו ושנו את המילים.
- לולאת רישום: לכל `ToolDef` — `server.tool(name, description, annotations=ToolAnnotations(read_only_hint=…,
  destructive_hint=…))(fn)`. `--tools read-only` משמיט את מה שאינו read-only.
- משאבים: `@server.resource("<שם>://rules")` סטטי; `about` / `models` / `ledger` חיים דרך `runner.run(...)` ורינדור
  לטקסט. פרומפטים: `@server.prompt(name=…)` שמחזיר מחרוזת עם סדר הפעולות.
- `main()`: argparse (`--db`, `--data-dir`, `--no-images`, `--tools`), `os.environ.setdefault("MPLBACKEND", "Agg")`,
  `logging.basicConfig(stream=sys.stderr)`, `server.run("stdio")`. את ערוץ ה-http (`web.py`) אתם לא צריכים.

### 5. אריזה
ב-`pyproject.toml`: `[project.optional-dependencies] mcp = ["mcp>=2,<3"]`; `[project.scripts] <שם>-mcp =
"nl2sql_accidents_starter.mcp.server:main"`; הוסיפו `nl2sql_accidents_starter.mcp` ל-`packages` (הרשימה לא
רקורסיבית — PITFALLS 2026-08-29); `mcp/knowledge/*.md` ל-`package-data`. התקינו מחדש (`pip install -e`), ובדקו
ש-`..\app\.venv\Scripts\<שם>-mcp.exe` קיים.

### 6. מבחנים
העתיקו את המבנה של `tests/test_mcp_tools.py` ו-`tests/test_mcp_server.py` והתאימו:
- המפה מכסה הכול; חתימות נקיות (אין פרמטר פנימי); `face` מתורגם ל-`view` של כל פעולה.
- כל סוג `Result` מרונדר (markdown/table/sql/chart/error); הקיצוץ ל-60 נאמר; המקרא מופיע.
- N הרצות כלי×מצב על ה-fixture הסינתטי שלכם (אותו `conftest.py` של ערכת הפתיחה) — בלי שגיאה.
- שורת audit לכל קריאה, ולעולם לא מספרים בתוכה.
- השער: אימון/פריסה בלי אישור לא נוגעים ברישום; מחזור אימון ← אימות ← פריסה עם אישור עובד על ה-fixture של
  הסטודיו. לבדיקת elicitation הלקוח בתוך התהליך חייב `mode="legacy"` (PITFALLS 2026-10-19).
- `Client(server)` בתוך התהליך: N כלים, enum בעברית בסכמה, משאבים, פרומפטים; ותת-תהליך stdio אמיתי
  (`python -m …mcp.server --db … --data-dir …`) — מוכיח ש-stdout נקי.

**מתיקייה ריקה** (אחרת המודל קורא את המספרים הצפויים מה-README שלכם במקום לקרוא לכלי).

## 6. מכשולים ידועים (כולם נרשמו ב-`PITFALLS.md` של הערכה)

- **`mcp` 2.x שינה את נתיב הייבוא:** `from mcp.server.mcpserver import MCPServer` (לא `fastmcp`). נעלו `mcp>=2,<3`.
- **החתימה היא הסכמה:** פרמטר עזר שחשפתם בחתימה הופך לשדה בטופס של המודל.
- **`confirm` הוא דגל, לא מנעול:** מודל ללא אדם מולו מעביר `confirm=true` בעצמו. השער האמיתי הוא elicitation;
  ובלקוח ללא ערוץ חוזר (הרצה ללא אדם) הקריאה נכשלת לפני ה-audit — לא נרשמת שורה.
- **הלקוח בתוך התהליך צריך `mode="legacy"`** כדי שבקשות מהשרת (הטופס) יעבדו במבחנים.
- **Desktop מחזיק את ה-exe של השרת בחיים** — `pip install -e` תחתיו נכשל באמצע ומשאיר חבילה חצי-מוסרת. עצרו
  את התהליכים קודם (המתקין של הערכה עושה זאת).
- **`claude.exe` הוא גם Claude Code וגם Desktop** — זהו תהליכים לפי הנתיב, לא לפי השם.
- **ל-Desktop שלושה מיקומי הגדרות** לאורך הגרסאות (`%APPDATA%\Claude`, ‏`…\Packages\Claude_*\LocalCache\…`,
  ‏`%LOCALAPPDATA%\Claude-Data\claude_*`). כתבו לכולם, ואמתו לפי התהליך ש-Desktop מריץ בפועל.
- **PowerShell 5.1 תחת `$ErrorActionPreference = Stop`** הופך שורת stderr של פקודה חיצונית לשגיאה עוצרת —
  עטפו קריאות ל-`claude mcp …` ול-pip והחליטו לפי קוד היציאה.
- **צ׳אט בדפדפן ≠ צ׳אט ב-Desktop:** הדפדפן לא רואה שרתים מקומיים. ואין שרת מתארח למסד הזה (למ״ס).
- **פלטי הכלים עוברים ל-API של Anthropic** — לפני שמרחיבים את קהל המשתמשים, זו שאלה למי שאחראי על הרישיון.
